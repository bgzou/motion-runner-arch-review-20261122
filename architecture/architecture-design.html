3.2.2 职责定位与一句话边界

业务主链路：用户说话/动作 → 大脑（听懂、认出、想清楚要做什么）→ 平台（仲裁：现在能不能做、先做哪件，并备好数据与算力）→ 小脑（怎么做：实时闭环把任务变成身体运动）→ 本体动作；全程由平台提供数据、算力、表现、安全与运行环境。本表为「层视角」（切清职责性质），与 §3.2.1 逻辑视图（模块构成）、§3.2.3「流视角」（交接物①~⑤）、§3.2.4「判据视角」（三问定责+负面清单）互补。

子系统 域性 职责定位（层视角） 一句话职责 一句话边界
大脑 Agent 子系统 认知决策域 认知与决策层（WHAT/WHY）：理解「做什么、为什么」 听懂、看懂、想清楚：把多模态输入理解成结构化意图，规划成任务序列，沉淀记忆 只产生「要做什么」，不仲裁、不执行、不碰关节
小脑子系统 技能执行域 运动与行为执行层（HOW）：决定「怎么动」 把任务做成运动：运控/导航/跟随三类运动技能独占式消费本体运动资源，实时决定「怎么动」并上报执行状态；融合感知、实时避障（暂定归此）产出目标/点云/代价图等结果级感知并实时改写避障，供三类技能与任务层消费 只管「怎么动」（含感知供给），实时域闭环，不关心用户是谁、说了什么

「融合感知 / 实时避障」边界注记（2026-11-13 决策）：

  2. 数据关系：实时避障只消费融合感知的输出（点云/目标），不自建感知链——避免本说明书多处批评过的「视觉链路重复建设」（T1 实证教训，§3.10.1）；
  3. 分层关系：与导航的避障分层——实时避障＝传感器级反射层（50ms tick 类、速度改写/限速，对标 coreon_fusion 避障链），导航＝规划级（代价图/绕行重规划，对标 nav2 costmap/behavior）；实时避障不参与输入源（控制权）抢占——它不调 /robot/mc/set_input_source（IF-TS-11）抢占、不注册源（T1 mc 注册源表 7 源无 coreon_fusion，EV-T1P-29），只对当前持权源的指令做安全叠写；极端停车走急停链（SystemFSM→E_STOP）而非抢源（避障改写后 velocity 的 source 名发布细节未实证，推断为复用被改写源语义）；
  4. 实现形态（已决策）：逻辑模块 ≠ 进程——「融合感知（融合引擎部分）+ 实时避障」同进程实现，对标 coreon_fusion「一个进程一份点云」的工程形态，避免 50ms 环上跨进程传点云；检测（person_track 类）与里程计（legged_odom 类）子组件可独立进程（T1 亦如此）。

3.7 业务流走查：一句「跟我走」（职责衔接验证）

以语音发起跟随为例，验证三个子系统在流程中各司其职、交接物清晰（T1 Pro 同场景实证见 UC3 [EV-T1P-28]）：

阶段 子系统 动作 交接物
1 感知理解 大脑 唤醒→ASR 出文本；视觉识别出「面前有人」上下文 —
2 意图 大脑 意图识别输出 {意图:跟随, 参数:-}（本地/云端两级仲裁） —
3 规划 大脑 规划判定为单步任务，直接下发任务意图 ① 任务意图 → 平台
4 准入与仲裁 平台 调度框架门控（电量≥阈值、odom 可信、无冲突任务）→ 获准；系统状态迁移至跟随态；拒绝则回统一 reason —
5 委派 平台 → 小脑 获准任务指令下发跟随模块 ③ 获准指令（source/token）
6 技能执行 小脑 跟随 FSM 启动：检测锁定目标（消费本子系统融合感知——感知视觉，非大脑交互视觉；数据由平台预处理就绪供给）→ 控制律输出速度 → 汇入运控控制权仲裁 → 关节执行 —
7 状态回灌 小脑 → 平台 跟随/运控域状态机持续上报 ④ 执行状态流
8 对外呈现与反馈 平台 状态聚合广播；本体 APP 镜像到 App/云，TTS/灯效播报「好的，跟你走」；全局状态反馈给大脑 ⑤ 状态/结果 → 外部与大脑
9 记忆更新 大脑 执行结果写入会话/任务记忆（断点可续） —
全程 平台·安全 低电/跌倒/失联任一触发 → 门控拒绝新任务或急停保护姿态，横向生效 —

结论：三个子系统的职责在流程中按「理解→治理→执行→反馈」串联，任一步只有一个子系统为责任方，边界可判定（对照 §3.2.4 三问）。

3.8 巴展场景业务流分析和模块间接口

3.8.1 巴展场景 A：主动迎宾、领路、站立讲解（业务流分析和模块间接口）

场景描述（阶段编号 A0~A4，A4 后回到 A0 循环）：

  • A0 待机迎宾：四足狗双足站立于展台入口，等待触发。触发为两条路径或门：① 观众说出唤醒词「你好，Collie」（语音唤醒）；② 观众靠近时，对人脸识别并与本体内预设 VIP 人脸库比对命中（主动人脸识别）。
  • A1 迎宾靠近与问候：唤醒后主动靠近观众、正面朝向观众，打招呼并主动询问「要不要带您去具身科技展台」。语音路径下经信标锁定（观众手持信标）确定目标观众，再由视觉识别提取观众特征。
  • A2 确认与领路：得到观众确认后，从双足变形为四足，开启领路模式带观众前往「具身科技展台」。领路依赖导航（导航向运控发布速度指令，从 A 点走到 B 点），过程中回看观众防止掉队。
  • A3 到达与站立讲解：到达后从四足变形为双足、正面朝向观众，讲解展台内容，手部搭配简单讲解动作；期间可回答观众提问。
  • A4 送别与返回循环（三步）：讲解完观众无进一步问题（Q&A 空闲超时/观众离开），依次执行三步——① 变形为四足；② 导航返回展台入口（无观众领带，不经领路，TE 直调导航）；③ 变形为双足站立——随后回到 A0 循环等待迎宾。

前置条件：场馆地图开机已加载（/robot/navi/load_map，非业务流）；VIP 人脸库预设完成；语音路径观众手持信标；讲解模块内置预置固定话术与讲解语音音频库（按音频 ID 播放，见要点⑦）。机型口径（2026-11-19 产品定义确认）：本产品支持双足站立＋四足↔双足变形——双足形态下前两腿转为双臂、后两腿站立承重，场景 A 的双足环节与讲解手势（双臂执行）即按此口径（README §3.3 A-2 已修订，OP-ARCH-07② 已裁决）。

3.10.2 差异注记

  1. 「大脑子系统」是对 T1 Pro 分布式现状的重组而非照搬：T1 Pro 的意图识别与场景编排住在 rk 的 task_engine 里、视觉在 orin、语音在 rk——认知能力物理上被拆在两板三处。本产品将其逻辑上归集为大脑子系统（板位是部署问题，见注记 4），收益是认知域可独立演进（换 LLM/加模态不动平台）；代价是必须显式定义「意图/计划 → 调度」的接口协议（可借鉴 T1 Pro 的 semantic_intent 话题 + AmRequest 服务形态，[EV-T1P-63][EV-T1P-27]）。
  2. 记忆是对标缺口（推断）：T1 Pro 端侧记忆证据仅到状态文件级（场景断点续跑 [EV-T1P-65]）与会话级（Agent 会话状态 [EV-T1P-16]），长期记忆（用户档案/偏好）在云端/App 侧，端侧证据不足。本产品记忆模块的分层范围（会话/任务/长期，端云边界）待产品定义（OP-ARCH-01）。
  3. 安全模块是收敛决策：T1 Pro 无独立安全模块，安全能力分散在 SM 急停 [EV-T1P-06]、任务规则门控 [EV-T1P-28][EV-T1P-37]、感知侧 IMU 姿态安全 [EV-T1P-44]、sys_guard 健康监控 [EV-T1P-20~22]、跌倒守护 reason 码 [EV-T1P-25]。本产品将其收敛为平台安全模块（统一安全状态/门控/监控/降级面），粒度与接口归 SEC 域章节展开。
  4. 部署注记：概念职责域 ≠ 板位。T1 Pro 实测形态即为例证：其「大脑」Agent 实际跑在 rk 运控板（非 orin——业务大脑 Agent 在 rk、感知/导航在 orin，主文档 §7.5 修正点①）；「小脑」拆在两板（运控在 rk 隔离核 CPU3 的 1kHz 实时环，导航/跟随及其感知视觉在 orin）；平台横跨两板——物理落板遵循「实时确定性 / 算力需求 / 大带宽数据不出采集板」三准则。本产品合理初值：大脑落感知算力板；小脑跨板（运控在实时运控板，导航/跟随在算力板）；平台随两板分布（调度与 OS 基座双板，预处理/推理重仓算力板）。具体板位属部署视图，随各特性域 X.5.6 细化（A-1 双板假设）。
  5. 「实时避障」在 T1 Pro 非独立模块；本产品列为逻辑模块但同进程实现（2026-11-13 决策）：T1 的避障内嵌于 coreon_fusion——BT 场景（scene_avoidance，tick 50ms）+ 服务面（SetAvoidance/ObstacleCheck）+ velocity 避障改写，与融合共用一个进程一份点云 [EV-T1P-39][EV-T1P-42][EV-T1P-43][EV-T1P-45]；而「跟随」是跨模块技能链（person_track＋follow_node＋coreon_fusion following 场景），避障作为横切反射能力同时服务跟随与导航（nav2 另有规划级避障）——两者在 T1 不平级（技能 vs 反射）。本产品仍将「实时避障」列为小脑独立逻辑模块（理由：① velocity 改写安全链路需明确归属与评审对象；② 50ms 反射与 30Hz 感知分属两档实时调度/降级策略；③ 跟随/导航/运镜多消费方的横切服务属性），实现上与「融合感知」的融合引擎同进程（边界三条见 §3.4 注记），兼得职责清晰与 T1 已验证的工程形态。
